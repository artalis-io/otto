Why OTTO

Trucking fleets in the US and EU face a brutal equation: thin margins, volatile fuel costs, complex Hours of Service regulations, and pressure to reduce environmental impact. Most fleets run far below optimal utilization.

OTTO exists to change that. By combining route optimization, fuel cost minimization, HoS-compliant scheduling, and real-time fleet planning, OTTO enables fleets to hit 2,000–3,000 loaded miles per week with 70–80% contract-to-spot ratios.

Superior utilization means fewer empty miles, lower fuel consumption per ton-mile, reduced emissions, and better margins. What's good for business is good for the planet.

Core Engines

Ralph C
LP/MIP solver engine. Revised Simplex with LU factorization, Branch & Bound, Gomory cuts.
73 tests · 23K loc · <100ms for 1000 vars
Velo C
OSM routing engine. Dijkstra, A*, bidirectional search, landmark preprocessing.
47 tests · 6.4K loc · <100ms country-scale
Carta C
Map tile generator. Vector tiles (MVT) and raster tiles (PNG) from OSM PBF.
33 tests · 11K loc · ~75ms per 512x512 tile
Locus C
OSM geocoding engine. Forward search, autocomplete, reverse lookup with trie + trigram index.
52 tests · 7.3K loc · <20μs per query
FuelWise C
Refueling optimization. LP formulation for minimum-cost fuel stops along a route.
33 tests · 2.9K loc · Uses Ralph solver
ClayShards C + JS
Immediate-mode UI components. WebGL renderer, MSDF fonts, map widgets.
84 tests · 9.5K loc · ~140KB WASM

Design Principles

Zero Dependencies
Core libraries use only standard C. No package managers, no supply chain risk.
WASM-First
All engines compile to WebAssembly. Same code runs in browsers and on servers.
Layered Architecture
Solver → Domain → API → UI. Each layer has a clean C API.
Arena Allocation
Bulk allocate, bulk free. No fragmentation, no leaks, cache-friendly.
Compound Literals
C11 features for inline configuration. Self-documenting, type-safe APIs.
Portable
Linux, macOS, Windows, browsers. Same codebase everywhere.
Secure by Design
No strcpy/sprintf, bounded buffers only. Arena allocators prevent use-after-free. Overflow checks on all allocations. WASM sandbox limits blast radius.
