Carta Tile Server
Default port: 8081

Serves vector tiles (MVT), raster tiles (PNG), and ASCII art tiles from OSM PBF files. Compatible with Leaflet, MapLibre, Google Maps, and OpenLayers.

GET /tiles/{z}/{x}/{y}.png Raster tile (PNG)

Path Parameters

Name Type Description
z required int Zoom level (0-18)
x required int Tile X coordinate
y required int Tile Y coordinate

Example

# Get tile at zoom 14, Budapest area
curl http://localhost:8081/tiles/14/9058/5729.png -o tile.png

Response

PNG image (512x512 by default). Content-Type: image/png

GET /tiles/{z}/{x}/{y}.mvt Vector tile (MVT/Protobuf)

Response

Mapbox Vector Tile format. Content-Type: application/x-protobuf. Use with MapLibre GL JS or similar vector tile renderers.

GET /tiles/{z}/{x}/{y}.txt ASCII art tile

Query Parameters

Name Type Description
width int Output width in characters (20-400, default: 80)
height int Output height (0=auto from aspect ratio)
charset string simple, extended (default), blocks, braille
invert bool 1 for light background terminals
color bool 1 for ANSI 256-color output

Example

# ASCII map in terminal
curl "http://localhost:8081/tiles/14/9058/5729.txt?width=120&charset=blocks"
GET /tiles.json TileJSON metadata

Response

{
  "tilejson": "2.2.0",
  "name": "OTTO Carta",
  "minzoom": 0,
  "maxzoom": 18,
  "bounds": [16.11, 45.74, 22.90, 48.58],
  "center": [19.50, 47.16, 7],

}

Velo Route Server
Default port: 8082

Route planning between coordinates with vehicle profiles, optimization modes, and Google Polyline encoded geometry. Uses A* with Landmarks for fast queries.

GET /api/v1/route Calculate route

Query Parameters

Name Type Description
from required string Origin coordinates (lat,lon)
to required string Destination coordinates (lat,lon)
profile string car (default), truck, bike, foot
mode string fastest (default), shortest
geometry bool Include polyline (default: true)

Example

# Route from Budapest to Debrecen
curl "http://localhost:8082/api/v1/route?from=47.497,19.040&to=47.531,21.627&profile=truck"

Response

{
  "status": "ok",
  "route": {
    "distance": 231245.5,
    "duration": 9123.4,
    "profile": "truck",
    "mode": "fastest",
    "from": [47.497, 19.040],
    "to": [47.531, 21.627],
    "geometry": "_p~iF~ps|U_ulLnnqC..."
  },
  "meta": {
    "nodes_explored": 12543,
    "search_time_ms": 34.5
  }
}

Vehicle Profiles

Profile Avoids
car Nothing (all roads)
truck Roads with hgv=no, residential, service
bike Motorways, trunk roads
foot Motorways, trunk, primary roads

Locus Geocoder
Default port: 8083

Forward geocoding (text search), autocomplete, and reverse geocoding (coordinate to address). Uses trie + trigram index for fast fuzzy matching.

GET /api/v1/search Forward geocoding

Query Parameters

Name Type Description
q required string Search query (UTF-8)
limit int Max results (default: 10, max: 100)

Example

curl "http://localhost:8083/api/v1/search?q=Budapest&limit=5"

Response

{
  "query": "Budapest",
  "total": 3,
  "took_ms": 0.12,
  "results": [
    {
      "osm_id": 21583,
      "osm_type": "relation",
      "name": "Budapest",
      "class": "place",
      "lat": 47.4979,
      "lon": 19.0402,
      "score": 1.0
    }
  ]
}
GET /api/v1/autocomplete Prefix completion

Query Parameters

Name Type Description
q required string Prefix to complete
limit int Max results (default: 10, max: 20)

Response

["Budapest", "Budaörs", "Budakeszi"]
GET /api/v1/reverse Reverse geocoding

FuelWise Optimizer
Default port: 8080

Refueling optimization using Linear Programming. Finds minimum-cost fuel stops along a route considering tank capacity, fuel prices, and consumption patterns.

POST /api/v1/solve Solve refueling problem

Request Body

{
  "total_distance": 500,
  "tank_capacity": 100,
  "current_fuel": 30,
  "consumption_mpg": 8,
  "minimum_fuel": 10,
  "stations": [
    {"id": 1, "distance": 100, "price": 3.50},
    {"id": 2, "distance": 250, "price": 3.25},
    {"id": 3, "distance": 400, "price": 3.40}
  ],
  "segments": [
    {"start": 0, "mpg": 6.0, "weight": 45000},
    {"start": 200, "mpg": 8.0, "weight": 30000}
  ]
}

Response

{
  "status": "optimal",
  "total_cost": 187.50,
  "purchases": [
    {"station_id": 2, "gallons": 45.5, "cost": 147.88},
    {"station_id": 3, "gallons": 11.7, "cost": 39.62}
  ],
  "final_fuel": 15.3,
  "solve_time_ms": 2.3
}
POST /api/v1/filter Filter stations to route

Request Body

{
  "stations": [
    {"id": 1, "lat": 34.0, "lon": -118.0, "price": 3.50}
  ],
  "route": [[34.0, -118.0], [33.5, -117.0]],
  "max_distance": 5
}

Response

Returns stations within max_distance miles of the route polyline, sorted by distance along route.

POST /api/v1/optimize Full optimization pipeline

Description

Combines station filtering and LP solving in one call. Accepts raw station coordinates and route polyline, snaps stations to route, and returns optimal refueling plan.

HTTP Status Codes

200 Success
400 Bad Request
404 Not Found
405 Method Not Allowed
422 Infeasible Problem
429 Rate Limited
500 Server Error
503 Queue Full
504 Request Timeout
